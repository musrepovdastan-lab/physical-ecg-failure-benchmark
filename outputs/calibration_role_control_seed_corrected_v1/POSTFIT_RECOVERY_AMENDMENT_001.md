# Post-fit recovery amendment 001

The frozen runner completed and passed the selection replay gate for all nine requested fits. Its first A-role score write then stopped with the exact exception `TypeError: atomic_npz() got multiple values for argument 'p'`: the writer used `p` as its path parameter while `p` was also the required prediction-array key. The failure happened after all nine training gates had passed and before any score NPZ was written; no fit was repeated.

To preserve the frozen runner and its recorded hash bindings, the recovery is a separate, hashed continuation (`postfit_recovery.py`). It re-verifies the frozen protocol and all nine training gates/checkpoint locks, does not call the trainer, writes the same protocol-defined A/B arrays atomically, reuses only previously verified detector caches, then fits the predeclared calibration and threshold locks. This is an implementation repair to the post-fit file writer; training, data roles, model, seeds, calibration specification, thresholds, and evaluation protocol are unchanged. The original failure log and frozen runner remain preserved.

Amendment authored before resuming post-fit computation. The initial post-fit exception and temporary recovery outputs are retained under `failed_attempts/`; they are explicitly excluded from valid scores and the final manifest's active-result inventory.


The first recovery attempt then exposed a second integration issue: the shared Huang adapter validates HEEDB's 12×5000 input, while the Ningbo calibration cache is 12×1000. A temporary direct-Ningbo continuation was implemented and produced A/B scores, but review against the already frozen `postprocess.py` showed it did not follow the specified full Huang path (load full 500-Hz ECG, apply the bound clean detector result, then use the frozen diagnostic preprocessing). Those temporary scores and locks are quarantined under `failed_attempts/postfit_recovery_direct_ningbo/` and are not valid analysis outputs. The accepted frozen `postprocess.py` is the canonical continuation and will regenerate the role scores and locks through the correct path. No test/HEEDB cohort was opened in that attempt, and no training was repeated.

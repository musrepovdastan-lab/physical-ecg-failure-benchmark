## 2. Короткий технический контроль циклов — перед расширением научных тестов

В существующем аудите есть расхождение между сохранёнными производными limb leads и их повторным вычислением из I/II: maximum 3.5 raw units, RMSE около 0.89. Влияние этого расхождения на предсказания отдельно не измерено.

На готовых ordinary/physics/combined ResNet моделях двух источников сравнить original clean с identity-rederived clean по тем же пациентам. Затем сопоставить с уже измеренными циклами. Никакого нового обучения. Зафиксировать объём и критерии до запуска; не объявлять расхождение безвредным по величине сигнала. При существенном влиянии потребуется согласованный контроль обработки, а не скрытая замена исторических clean результатов.

## 3. Смесь трёх swaps — добавить

Расширить существующий анализ clean/RA–LL на RA–LL, RA–LA и LA–LL. Использовать готовые модели, существующие пороги и calibrators; новые предсказания считать только для отсутствующих условий. Начальный ограниченный набор: ordinary, physics p050, combined; Huang включать только с его реальным detector/correction pipeline и проверенной поддержкой условий, без oracle-коррекции.

Сохранить прежнюю сетку общей частоты faults q. Первичная смесь: по 1/3 каждого swap среди неисправных записей; RA–LL-only оставить сравнением. Это условный сценарий, не установленная клиническая распространённость. Сначала source evaluation и проверка корректности, затем прежняя внешняя HEEDB когорта при наличии всех prediction bindings. Копии одной записи не считать независимыми пациентами; bootstrap синхронизировать. Все новые сравнения после прежнего доступа к данным считать расширением exploratory анализа.

## 4. Независимая калибровка — стоит сделать ограниченный контроль

Проблема: все прежние validation записи использовались для выбора checkpoint до разделения на calibration A и threshold B. Это не fitting на test/HEEDB, но calibration не отделена от выбора модели. Величина возможного влияния пока неизвестна; старые результаты не отменяются автоматически.

Сначала preflight: проверить существование действительно неиспользованного подходящего source holdout и достаточность числа положительных/отрицательных примеров для каждого endpoint. Нельзя назвать независимыми ранее использованные train/validation/test записи простым переименованием.

Если отдельного подходящего holdout нет, подготовить заранее фиксированный контроль на Ningbo: исходный train без добавления calibration записей; patient-disjoint validation части для checkpoint selection, calibration fit и threshold selection. Старые checkpoints не подходят для этой новой схемы. Минимальный основной набор — ordinary, physics p050, combined, по три seeds, максимум девять новых обучений; точный split и достаточность классов определить в preflight. Не повторять всю p-grid, все архитектуры и 792 маски ради этой проверки.

Для Huang по возможности использовать соответствующий новый ordinary диагностический классификатор внутри полного pipeline с замороженным detector; собственные calibration/threshold fit выполнять по тем же правилам. Иначе не делать вывод о превосходстве над Huang из несопоставимых процедур.

Заморозить гиперпараметры, splits, q и критерии до запуска. Сравнить raw/calibrated Brier, ranking, чувствительность и ложные тревоги на source test и прежней HEEDB; не выбирать рецепт по HEEDB. Дизайн предложен после прежних результатов и HEEDB уже исследована: называть это проверкой устойчивости выводов к процедуре калибровки, а не совершенно новой независимой внешней репликацией. Предварительная историческая разработка гиперпараметров также должна быть раскрыта.

## 5. Transformer — сохранить завершённый смешанный результат

Chapman TimePatchTransformer: mean RA–LL TWA AUPRC примерно 0.2183 → 0.6045; все три seeds улучшились. При этом один seed потерял 0.1126 mean-mask AUPRC при допустимом лимите 0.04. Integrity прошла. Заранее установленный gate не пройден; условный Ningbo/HEEDB этап не запущен.

Не повторять обучение до получения PASS и не делать вывод обо всех Transformer. Founder frozen-head контроль уже даёт дополнительную архитектуру, но не доказывает универсальность и не заменяет полного finetuning. Возврат к Transformer оправдан отдельным вопросом о стабильности, а не необходимостью убрать неудобный результат.

## 6. Дополнительные идеи — осознанно отложить

- Leave-one-swap-out: самый содержательный следующий тест обобщения после основных задач, если останется ресурс. Не является дублем циклов, но его прирост к уже имеющимся невиданным композициям ограничен. Новизну самого augmentation не создаёт.
- Шум/контакт вместе со swap: полезно для расширения реализма; выбирать конкретную проверяемую гипотезу и обоснованные уровни. Сейчас не открывать полный noise benchmark.
- Реальные подтверждённые miswirings: сильное внешнее усиление при появлении подходящих записей, не обязательное условие simulation study. Не предполагать наличие готового датасета у клиницистов.
- Массовый benchmark архитектур: нужен для утверждения о лучшей архитектуре; такого утверждения у нас нет. Не запускать только ради числа моделей.
- Память/новые устройства/12-канальный chest control: сейчас низкий приоритет; существующий runtime вывод ограничить измеренной интеграцией.
- Клиническая трактовка endpoints и proxy mappings остаётся открытой задачей; готовый пакет вопросов не считать ответами врача. Это отдельная работа, не запрос на создание клинического датасета.
